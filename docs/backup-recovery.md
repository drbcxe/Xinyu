# 加密备份与隔离恢复

本工具面向当前单机开发环境。备份存放在 D 盘，不上传第三方；恢复演练只创建随机隔离库/集合，验证后删除，不覆盖正在使用的业务库。它不是已上线的灾备系统，也没有完成异地恢复或生产切换。

## 备份内容与密钥

- PostgreSQL 的 `public` 业务表和 `xinyu_graph` 检查点，包括表结构与数据。共享导出快照保证转储和逐表指纹来自同一个数据库视图。
- 当前 `xinyu_<16位索引签名>` 向量集合的 Qdrant 快照。每份快照先恢复到临时集合计算内容指纹，演练时再次核对向量与 payload；SQL 与向量库不是跨服务原子快照，恢复时仍以 SQL 来源/版本为准。
- 本地 `.env` 与 `auth-captcha.key`、`email.key`、`weixin.key`、`ops.key` 中实际存在的密钥，整体加密。不存在的邮件/微信密钥不会假装已配置。
- 独立的加密删除意图记录。原科研文件夹和 `researchmate_archive` schema 不在范围内；如果发现意外的非心语 public 表，工具拒绝混入其他数据。

每个文件使用独立随机 nonce 的 AES-256-GCM 加密并绑定备份 ID/文件名；加密清单记录 SHA-256 和大小。只有全部完成后才写 `COMPLETE` 标记。备份主密钥单独保存在 `.runtime/backup-keys/master.key`（也可本地设置 `BACKUP_KEY_FILE`），**不会放进备份目录**。生产模式必须显式配置其路径。备份目录、主密钥和最新删除记录均不能提交 Git。

主密钥丢失无法解密。当前 D 盘的备份和密钥仍共享同一故障域；用户需要另存到自己控制的独立介质或私有存储，保留最新删除记录。工具没有擅自上传或选择外部服务。Windows 目录权限沿用当前用户的私有工作目录；正式部署需要设置受限 ACL/Unix 权限和独立备份账号。

## 本地操作

```powershell
Set-Location -LiteralPath 'D:\Study\简历\Xinyu'
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m scripts.backup create
# 使用上一条返回的完整目录
.\.venv\Scripts\python.exe -m scripts.backup drill 'D:\Study\简历\Xinyu\.runtime\backups\xinyu_backup_时间_标识'
.\.venv\Scripts\python.exe -m scripts.backup prune --days 7 --keep 3
```

运行需要本地 Docker、PostgreSQL 与 Qdrant。先比对数据库连接与 PostgreSQL 容器的集群标识，避免转储了同名的其他库。可用 `XINYU_PG_CONTAINER` 显式指定准确的容器 ID；CI 使用独立服务容器。每个数据库转储/恢复进程有五分钟上限；单个备份组件上限 2 GiB，超过时失败，不产生“成功”标记。模型接口不会参与备份或演练。

清理策略：保留最近 3 份完整备份，其他完整备份满 7 天后可由 `prune` 或新备份的预清理移除。因此停止新备份时，最后 3 份可能超过 7 天，不能把这个策略说成严格七天销毁。只处理指定根目录中符合工具命名且有完整标记、仅包含工具组件的普通目录，先检查解析后的绝对路径，不删除其他文件或主密钥。未完成的备份需查明失败后手动处理，不计为可用副本。本阶段提供显式命令，没有创建自动定时任务。

默认根目录合计 8 GiB、最多 128 个备份目录，未完成目录也占用容量和数量；超过时拒绝新备份，不删除最近恢复副本来强行完成。创建、保留清理和演练共用根目录文件锁，避免正在使用的副本被另一进程删除。流式加密在每次写入前预留字节，包括文件头/认证标签；失败时仅清理本次新建且仍符合工具结构的残片目录。恢复临时文件全局上限 4 GiB，逐组件累计计入已有残留；默认至少留下 2 GiB 文件系统空闲。超过临时空间上限的备份不会标记完成。详见 [运行文件容量](./runtime-file-budgets.md)。

## 恢复演练做什么

1. 先验证全部加密组件和大小/指纹；错误密钥、文件损坏、上下文不匹配均停止。认证失败的文件不会交给数据库执行。
2. 创建 `xinyu_restore_<随机标识>` 数据库，再导入结构/数据，逐表比较行数与逻辑内容指纹，包括实际图检查点。
3. 用恢复出的本地密钥解密验证非空的邮件/微信密文，核对密钥与业务数据配套；不发送邮件或微信消息。
4. 重放最新删除意图，按恢复时刻和已发生的过期边界移除应删除内容，避免恢复旧备份带回已注销账号、已清空内容、删除的单条资料和反馈。
5. 恢复向量到另一个随机集合，核对内容指纹，然后移除对应账号/资料的向量。清空之后新增的资料会保留，其索引标为待重建。
6. 删除恢复出的登录会话、邮件挑战/投递和微信绑定，取消旧排队/运行任务，撤回 AI 处理授权，防止旧任务或权限自动续用。不会加载恢复的 `.env` 启动服务。
7. 最后删除本次隔离库、集合和临时文件，返回聚合报告。源库、源向量集合和备份原件保留。

数据库转储直接流式加密；向量校验和恢复会在 D 盘 `.runtime/restore-tmp` 创建受限临时明文文件，通过认证后才使用，正常退出或异常会清理。恢复操作持跨进程排他锁；目录中的零字节 `.restore.lock` 是保留的锁文件，不含恢复数据。强制断电/终止可能留下临时目录，残留继续计入容量；重启后先核对具体演练进程是否结束，再清理该次目录，不能盲删其他恢复任务。

## 删除如何跨备份生效

注销、清空、单条删除、反馈删除、保留设置和后台过期在提交数据库事务前写入 `.runtime/recovery/deletions.log`，加密并 `fsync`。日志只含空间哈希、作用域、随机资料 ID/过期边界与时间，不保存聊天、邮箱或密码。即使数据库提交失败，保守保留删除意图，恢复时仍排除相关旧副本；这是隐私优先的取舍。

清空意图带时间边界，不能误删后来新增的数据；过期意图保留已清理的截止时间，之后延长保留期限也不会重新带回这些记录。账号关闭使用持久哈希墓碑，防止旧 Cookie 重建原空间。自动过期仍保留用户确认的偏好摘录。

恢复需要**最新**删除日志；默认文件缺失或截断则停止。日志是认证记录，不是防恶意回滚的外部不可变账本，不能只拿旧备份里的日志冒充最新日志。它与主密钥也需要独立保存。演练期间新发生的删除在读取时纳入；正式切换前必须先停写，再用最后日志重放并验收。

## 故障恢复与切换边界

本地演练报告只证明该份备份可被隔离读取、恢复与校验。真实故障时先停止应用写入和 Worker，确认备份、配套主密钥、最新删除日志及数据库/Qdrant 版本；在新的目标环境恢复并重放删除/过期规则，使用新的空 Redis，会话、渠道和 AI 授权重新建立；验收后才修改连接配置并启动服务。不要直接解密后覆盖生产文件，也不要跳过删除过滤启动 Worker。

生产切换工具、域名/HTTPS、异地副本和 RPO/RTO 承诺随部署阶段另做。当前为按需备份，RPO 为距最后成功备份的时间；没有 WAL/PITR 连续恢复。小型本地样本的一两秒演练耗时不能当作生产恢复 SLA。

验收包括实际 PostgreSQL/Qdrant/图状态恢复、备份后注销、分作用域删除、保留期限延长不复活过期内容、密钥解密配套、损坏文件拒绝和隔离资源清理。当前业务数据已完成一次 D 盘加密备份及隔离演练，私有聚合结果在 `.runtime/backups/last-drill.json`；仓库不包含这些数据。

依据：[PostgreSQL pg_dump 导出快照](https://www.postgresql.org/docs/current/app-pgdump.html)、[Qdrant 快照恢复](https://qdrant.tech/documentation/operations/snapshots/)。
