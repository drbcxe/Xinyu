# 运行文件容量与本地进程

数据库行预算和向量数量准入不能限制日志、备份及恢复明文。现在分别为这些工具写入的文件增加总量边界；运行目录仍在 D 盘，原科研目录不参与清理。

| 本地配置 | 默认值 | 生效范围 |
| --- | --- | --- |
| `LOG_FILE_BYTES` / `LOG_BACKUP_COUNT` | 4 MiB / 2 | 单个受管 PID/角色的当前日志及轮转文件 |
| `LOG_TOTAL_BYTES` / `LOG_RETENTION_DAYS` | 128 MiB / 7 天 | 当前根目录所有 `app-角色-PID.jsonl[.序号]` 文件 |
| `BACKUP_TOTAL_BYTES` / `BACKUP_MAX_COUNT` | 8 GiB / 128 | 指定备份根目录现有字节与备份目录数量，包括未完成残片 |
| `BACKUP_RETENTION_DAYS` / `BACKUP_KEEP_COUNT` | 7 天 / 3 份 | 最新完整副本始终保留，其余完整副本到期才可清理 |
| `RESTORE_TEMP_BYTES` | 4 GiB | 默认恢复临时根目录内所有文件，包含旧的异常残留 |
| `RUNTIME_FREE_BYTES` | 2 GiB | 日志、备份及解密每次写入前要求的磁盘剩余空间 |

修改本地 `.env` 后重启相应进程。降低上限不会自动销毁受保护副本；超限后允许检查和人工处理，不接受继续增长。配置要求保留数量不大于备份数量上限，日志轮转至少保留 1 个历史文件。

日志写入、轮转和清理在同一跨进程文件锁中执行，先核算再写；日志锁争用最多等待 0.1 秒，超额或磁盘不足时丢弃本次日志。不会通过错误回退把原始日志打印到 stderr。PID 存活探测在 Windows 使用进程查询 API，不使用会终止目标进程的 `os.kill(pid, 0)`。已退出 PID 的旧文件才可按时间/容量回收；PID 被复用或查询受限时保守保留。非本工具日志、链接和未知结构不自动删除。

`scripts/start.ps1` 通过三个 supervisor 启动 API、Worker 和前端；原始输出持续按固定块排空，只记录安全的角色/流/字节数/退出码。应用事件仍由脱敏 JSON 格式器记录。启动前拒绝占用端口，发现失败仅停止记录中由本工具启动的服务。停止时核对 PID 与准确启动时间，沿进程树反向结束，逐个复核创建时间和父进程，避免 Windows 虚拟环境转发进程留下后代，或误认复用的 PID。

备份创建、演练和清理对同一备份根目录串行；恢复明文另有排他锁。加密文件头、数据和认证标签均计入预算，解密按所有已展开组件累计计入临时上限。失败后只清理本次拥有的普通目录；存在未知文件时保留并由运维告警提示。锁文件故意保留为零字节，防止删除锁 inode 后另一个进程绕过互斥。

受保护的 `/api/ops/status` 的 `storage.runtime_files` 提供日志字节、上限、备份数量/未完成数、临时字节及最小空闲要求；90% 用量、未完成备份、测量失败和当前 API 进程丢日志触发本地告警。丢日志计数属于响应进程，不是各 Worker/supervisor 的集群累计。服务返回不包含备份内容、路径、密钥或用户数据。

这些数字按普通文件逻辑长度核算，不是文件系统已分配簇、保留空间或操作系统硬配额。外部程序、不同配置根目录的进程、PG 数据/WAL、Qdrant 快照与磁盘压缩、Docker VHDX、缓存和恢复出的隔离数据库/集合不受本文件预算覆盖；这些服务仍需独立的卷容量、告警和生产配额。独立的恢复删除意图日志也不能按进程日志轮转删除，其持续增长与保持删除语义的容量安排仍在 E11 待验收。并行写不同根目录会竞争磁盘，空闲空间检查不能预订整个文件系统；真实 ENOSPC 仍按写入失败处理。不能把本功能说成“所有物理磁盘增长已受硬限制”。
